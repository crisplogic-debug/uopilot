1. ОБЩЕО ОПИСАНИЕ
================================================================================

uopilot — приложение с GUI для:
  • сбора кадров из окна игры;
  • ручной разметки объектов на изображениях;
  • обучения и дообучения ML-модели;
  • распознавания объектов в области окна игры в реальном времени.

Первичный кейс: столбик прогресса (белая заливка, прозрачная пустота, зелёная
perfect zone вверху) — числовая характеристика = доля заполненности [0..1].

Платформа: Windows 10/11, Python 3.11+, PyQt6/PySide6, ONNX Runtime / TensorRT
(GPU NVIDIA RTX 4080). Latency ML-инференса: < 10 мс (p95).

2. БАЗА ОБЪЕКТОВ И СТРУКТУРА ДАННЫХ
================================================================================

2.1. База объектов
------------------
Справочник объектов по наименованию. Каждый объект — отдельная сущность
с собственными каталогами изображений.

  data/objects/<object_name>/
    raw/                  — исходные кадры, требующие разметки
    labeled_train/        — размеченные кадры для обучения
    labeled_val/          — размеченные кадры для валидации

  Пример object_name: fishing_bar, round_target, ...

  Реестр объектов: data/objects/registry.json
    [ { "name": "fishing_bar", "description": "Столбик заброса удочки" }, ... ]

2.2. Пары файлов «изображение + разметка»
-----------------------------------------
  • Изображение и файл разметки лежат в одном каталоге.
  • Имена совпадают, отличается только расширение:
      frame_0042.png
      frame_0042.json

2.3. Формат файла разметки (JSON)
---------------------------------
  {
    "object_name": "fishing_bar",
    "polygon": [[x1, y1], [x2, y2], [x3, y3], ...],
    "center": [cx, cy],
    "value": 0.72
  }

  Поля:
    object_name  — наименование объекта из базы (строка)
    polygon      — полигон области объекта на изображении (список точек [x, y]
                   в пикселях, координаты относительно изображения)
    center       — координаты центра объекта [cx, cy] (пиксели)
    value        — числовая характеристика объекта, float [0.0 .. 1.0]
                   (вводится пользователем; напр. доля заполненности столбика)

2.4. Правила каталогов
----------------------
  raw/              — кадры без JSON-файла разметки (требуют разметки)
  labeled_train/    — кадр + JSON; используется при обучении
  labeled_val/      — кадр + JSON; используется при валидации, не в обучении

  Перемещение между каталогами: при сохранении разметки пользователь выбирает
  «для обучения» или «для валидации» — файл перемещается (или копируется)
  из raw/ в соответствующий каталог вместе с JSON.

3. АЛГОРИТМ РАБОТЫ ML-МОДЕЛИ
================================================================================

3.1. Вход
---------
  • Область окна игры — прямоугольный кадр произвольного размера
    (до 1920×1280 px).
  • Кадр подаётся на вход модели как изображение (RGB/BGR, нормализованное).

3.2. Выход (на каждый обнаруженный объект)
------------------------------------------
  {
    "object_name": "fishing_bar",
    "center": [cx, cy],
    "value": 0.72,
    "confidence": 0.95
  }

  Поля:
    object_name  — распознанный объект из базы
    center       — центр объекта на изображении [cx, cy]
    value        — числовая характеристика [0.0 .. 1.0]
    confidence   — достоверность результата [0.0 .. 1.0]

3.3. Логика
-----------
  1. Захват области окна игры.
  2. Подача кадра в модель.
  3. Модель детектирует объекты из обученного набора классов.
  4. Для каждого объекта возвращает center, value, confidence.
  5. Приложение использует результат (сигнал, автоклик и т.д.) по настройкам.

3.4. Модель
-----------
  • Архитектура: детектор (YOLOv8n) + регрессионная голова value на кропе объекта.
  • Один ONNX/TensorRT-файл на версию модели; список классов = object_name из базы.
  • Дообучение: загрузка существующей модели + новые размеченные данные.
  • Сохранение: models/<model_name>/<version>/model.onnx + config.json (классы,
    input_size, нормализация).

4. GUI ПОДГОТОВКИ ДАННЫХ ДЛЯ РАЗМЕТКИ
================================================================================

Отдельное окно приложения.

4.1. Элементы интерфейса
------------------------

  A. Привязка окна игры
     • Кнопка / горячая клавиша Ctrl+A — выбор и привязка окна игры для захвата.
     • После привязки отображается заголовок окна и его размер.

  B. Область сбора
     • Выбор прямоугольной области внутри привязанного окна (мышью на превью).
     • Отображение размера области в пикселях.

  C. Выбор объекта
     • Выпадающий список объектов из базы (data/objects/registry.json).
     • Собранные кадры сохраняются в data/objects/<object_name>/raw/.

  D. Управление записью
     ┌──────────────────┬────────────────────────────────────────┐
     │ Действие         │ Горячая клавиша                        │
     ├──────────────────┼────────────────────────────────────────┤
     │ Привязка окна    │ Ctrl+A                                 │
     │ Старт записи     │ Ctrl+S                                 │
     │ Стоп             │ Ctrl+D                                 │
     │ Пауза            │ Ctrl+F                                 │
     └──────────────────┴────────────────────────────────────────┘

  E. Индикаторы
     • Статус: ожидание / запись / пауза.
     • Счётчик сохранённых кадров, длительность сессии.
     • Путь сохранения: data/objects/<object_name>/raw/.

4.2. Поведение при записи
-------------------------
  • Захват выбранной области с заданной частотой (по умолчанию 10 FPS).
  • Имя файла: <timestamp>_<index>.png (уникальное, без коллизий).
  • Запись асинхронная, не блокирует GUI.
  • Автосохранение размеров и положения окна при изменении.

================================================================================
5. GUI РАЗМЕТКИ ДАННЫХ
================================================================================

Отдельное окно приложения.

5.1. Навигация
--------------
  Левая панель — дерево:
    Объект (fishing_bar, ...)
      ├── raw/                  (требуют разметки)
      ├── labeled_train/        (размечены для обучения)
      └── labeled_val/          (размечены для валидации)

  При выборе каталога — список изображений (миниатюры).
  При выборе изображения — открывается в центральной панели.

5.2. Дашборд (верхняя панель или боковая сводка)
------------------------------------------------
  Таблица по каждому объекту:
  ┌──────────────┬───────────┬────────────┬─────────────┐
  │ Объект       │ raw       │ train      │ val         │
  ├──────────────┼───────────┼────────────┼─────────────┤
  │ fishing_bar  │ 120       │ 850        │ 150         │
  │ round_target │ 45        │ 0          │ 0           │
  └──────────────┴───────────┴────────────┴─────────────┘

5.3. Процесс разметки одного изображения
----------------------------------------
  1. Выбрать объект (из базы) — определяет object_name в JSON.
  2. Нарисовать полигон области объекта на изображении (клики — вершины,
     двойной клик / Enter — замыкание полигона).
  3. Указать центр объекта (клик инструментом «Центр»).
  4. Ввести числовое значение value [0..1] в поле ввода.
  5. Сохранить — выбрать назначение:
       [ ] для обучения  → labeled_train/
       [ ] для валидации → labeled_val/
  6. Создаётся JSON рядом с изображением; пара файлов перемещается
     из raw/ в выбранный каталог.

5.4. Визуализация разметки на изображении
-----------------------------------------
  • Полигон — линия контура + полупрозрачная заливка.
  • Центр — маркер (крест или точка).
  • Подпись: object_name, value.
  • При открытии уже размеченного файла — маркеры отображаются из JSON.

5.5. Навигация по кадрам
------------------------
  • Кнопки ← / → или список миниатюр — переход между изображениями каталога.
  • Горячие клавиши: Ctrl+S — сохранить, Delete — удалить разметку, Esc — сброс.

5.6. Автосохранение
-------------------
  • Прогресс разметки текущего кадра сохраняется при переходе к следующему.
  • Автосохранение размеров и положения окна при изменении.

6. GUI ОБУЧЕНИЯ МОДЕЛИ
================================================================================

Отдельное окно приложения.

6.1. Режимы
-----------
  • Создать новую модель — обучение с нуля.
  • Дообучить существующую — выбор модели из списка (models/), загрузка весов.

6.2. Выбор данных
-----------------
  • Каталоги для обучения: мультивыбор объектов и/или каталогов labeled_train/.
  • Каталоги для валидации: мультивыбор labeled_val/.
  • Счётчик: N изображений train, M изображений val (по выбранным каталогам).

6.3. Параметры обучения (с рекомендуемыми значениями по умолчанию)
--------------------------------------------------------------------
  ┌────────────────────┬──────────────┬─────────────────────────────┐
  │ Параметр           │ По умолчанию │ Пояснение                   │
  ├────────────────────┼──────────────┼─────────────────────────────┤
  │ Эпохи              │ 50           │ early stopping patience=10  │
  │ Batch size         │ 16           │ уменьшить при нехватке VRAM │
  │ Learning rate      │ 0.001        │ 0.0001 при дообучении       │
  │ Input size         │ 640          │ letterbox до 640×640        │
  │ GPU                │ вкл          │ RTX 4080, FP16              │
  └────────────────────┴──────────────┴─────────────────────────────┘

6.4. Ход обучения
-----------------
  • Прогресс-бар эпох, график loss (train / val) в реальном времени.
  • Текущие метрики: mAP, MAE value, loss.
  • Лог текстом (прокручиваемое поле).
  • Кнопки: «Старт», «Стоп», «Сохранить модель».
  • По завершении — сохранение в models/<name>/<version>/, запись в реестр.

================================================================================
7. ИНФЕРЕНС (БОЕВОЙ РЕЖИМ)
================================================================================

  • Привязка окна игры + область захвата (как в разделе 4).
  • Выбор подключённой модели из реестра.
  • Цикл: захват → модель → вывод object_name, center, value, confidence.
  • Настройка порога confidence и действия при срабатывании (сигнал / автоклик).
  • Отображение latency и результатов на оверлее или в панели.
  • Горячая клавиша экстренной остановки автоклика.

================================================================================
8. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ
================================================================================

  Производительность:
    • ML-инференс p95 < 10 мс на RTX 4080 (область до 1920×1280).
    • Захват и запись не снижают FPS игры более чем на 5%.

  Железо (референс):
    • GPU: NVIDIA RTX 4080
    • CPU: Intel i5-14700
    • RAM: 64 GB DDR5

  DPI:
    • Поддержка масштабирования Windows 100–200%; координаты полигона и центра
      — в пикселях захваченного изображения.

  Надёжность:
    • Данные хранятся локально.
    • При ошибке модели — режим «только сигнал», без автоклика.
